# Vue 3 工作台：使用、验收与回滚

## 使用流程

1. **工作区**：输入名称创建项目，或继续 DGX 保存的项目。`?project=<id>` 保留；`?job=<id>` 是只读历史任务，可明确导入为新工作区。
2. **要求描述**：输入用途、行为和限制，回答 Qwen 的必要问题。预算可不填；不擅自指定币种、零件购买或打印机。
3. **微调细节**：草稿标为概念、未验证。先看比例和设计说明；没有说明的旧版本显示缺失，后续 AI 回答不冒充当时的设计依据。
4. **可行性验证**：主动确认后，对已保存设计运行现有工程工具及有界修复。需求改动后先重新生成草稿；不能拿旧模型验证新需求。
5. **导出和装配**：同一版本的打印件 / 采购件、BOM、接线、固件、装配、打印机和切片。关键检查失败时仅提供明确标记的诊断资料，并禁止装配确认和切片。UNKNOWN 不等于物理通过。

## 选件与 AI

- 点击单选，Shift 点击增减选择；活动零件显示属性，全部选中件进入 AI 请求。
- **询问**只解释；不会生成 CAD、验证或覆盖设计。
- **微调**优先生成字段级候选和理由，不重写未变化的零件；涉及新增零件、接线或装配说明时明确转回完整设计通道。相关支架 / 外壳 / 线路的变化均列入清单，先比较再确认。
- 等待回复时可先起草下一条，发送暂时禁用；回复不会清空新草稿。状态卡显示真实耗时及提交时冻结的零件，不编造生成百分比。
- 修改追问显示“继续补充这次修改”和原请求，可选择“开始新修改”。中途切到只读询问后，点击追问答案会恢复该次修改模式与原零件上下文，但不会自动发送。版本变化或修改结束后，历史答案停用；更换选中零件时不再自动拼接上一条修改。
- 请求发送时冻结 `expectedRevision`、`designHash`、`selectedPartIds`。服务端自行解析真实零件；浏览器不是权威数据源。
- 候选预览中的新增件也能选中、隐藏和只读提问。其选择只留在预览中，显示偏好保存时排除尚未确认的 ID；关闭预览会清除这些选择，不产生幽灵零件或设计写入。
- 过期候选不能应用。确认后产生新版本，旧证据不再作为当前版本证据，历史文件仍保留。
- 需求页在没有 CAD 时也可只读问答；先保存当前需求，问答不会自动开始生成。修改模型仍须进入微调阶段。
- 最近 40 轮成功对话独立保存到 DGX，刷新后恢复；最近 8 条有界历史进入追问上下文。历史回复不是工程证据，不覆盖当前版本事实。候选预览和装配勾选仍是临时交互；刷新不会自动应用候选。
- 真实生成进度显示模型、耗时、已接收字符数；字符数不是完成率。模型断线和拒绝结果明确显示，每次已完成的输出及失败理由在下一次重试前保存。
- 本地推理的元数据读取、输出流和 runner 错误读取均受原请求截止时间约束。底层流取消未完成时，不会为了等待清理而无限延迟错误反馈；这不提高模型几何正确率。

## 视口操作

| 操作 | 按键 / 鼠标 |
| --- | --- |
| 旋转 / 平移 / 缩放 | 中键拖动 / Shift + 中键 / 滚轮 |
| 前 / 右 / 顶视图 | 小键盘 1 / 3 / 7；Ctrl 组合为反面 |
| 透视 / 正交 | 小键盘 5 |
| 聚焦所选 / 适配可见 | 小键盘小数点 / Home |
| 隐藏所选 / 隐藏未选 / 全部显示 | H / Shift + H / Alt + H |

六向视图、聚焦、适配和显隐也有屏幕按钮，不要求数字键盘。快捷键只在视口聚焦时生效，不拦截输入框。隐藏零件不再被视口射线拾取，但仍可在大纲选中和恢复；相连线路跟随端点显隐。显隐不改变设计哈希、验证、采购或导出。本轮不支持 G/R/S 或直接几何编辑。

原生模型采用毫米坐标并校验 STL 哈希。下载 / 校验失败会显示错误，不会悄悄换成好看的概念模型。窄屏右侧面板为可关闭抽屉；尊重系统减少动态设置。

## 开发与验收

```sh
npm ci
npm run check:source       # 缺少私有资产时的独立源码验收
npm run check              # 具有完整组件资料的回归
npm run test:e2e           # 独立模拟接口，不接触生产 Qwen/打印机
python3 tests/submission_package_test.py
```

浏览器测试先准备 Playwright Chromium，或设置 `M4KE_BROWSER_EXECUTABLE`。测试记录写入新的 `test-results/` 子目录；不能把夹具截图当成真实 Qwen / CAD / 实物证明。

真实 DGX 验收必须在隔离应用和独立数据目录执行：新建草稿 → 选件询问 → 候选修改 → 确认 → 原生验证。记录实际模型、项目 / 设计哈希、候选和检查结果；失败也保留。成功完成交互不意味着小车实物可工作。

## DGX 切换与回滚边界

1. 与队友协调停用窗口，停止新请求；检查设计、构建、切片任务和在途模型请求。仅观察任务文件不能完全证明没有在途只读请求。
2. 在唯一隔离目录验证新包。只传审核白名单内的应用源码、前端产物和必要运行依赖；不覆盖项目数据、模型权重、模型库或队友目录。
3. 备份将覆盖的代码、服务单元和配置，记录新文件清单及哈希。备份目录私有，不加入源码包。
4. 更新后检查服务、前端入口资源、模型配置和关键浏览器流程；不把 HTTP 200 当成全部验收。
5. 失败即恢复旧**应用代码和服务单元**；不回滚用户项目数据。之后修改过的文件如不匹配部署哈希，应拒绝盲目回滚，先人工协调。

设备私有的部署工具与端点不会进入开源包；公共安装方法见 [部署文档](submission/DEPLOYMENT.md)。具体部署 / 回滚记录以本次测试和备份收据为准。


## 2026-09-29 工作台视觉更新

保持五阶段和版本/验证规则不变，仅借鉴 Mixos 的空间布局与质感，不复制品牌、图标素材，不添加手工网格编辑、动画或时间轴。顶部当前阶段操作、深色内嵌视口、悬浮工具、右侧大纲/属性卡片与底部对话保持同一空间位置。需求页使用意图预览与真实进度，而不是假 3D 预览或模拟百分比。

视口仍只创建一个 Three.js 控制器；选择、显隐和对话展开不重建模型。色彩/光照的视觉调整不改变 CAD、毫米坐标、导出或物理结果。支持减少动态、减少透明度及更高对比度。历史消息保持其真实模型身份。

确认候选时，除了设计要求/检查目标，打印耗材的派生规格说明变化也需要明确同意。改变数量、SKU、来源或自动修复的不可变内容依然拒绝。
