## Public source approval — 2026-09-29

The owner has now explicitly approved publishing `frabcd/M4KE` publicly under
the existing MIT licence for original code, using the supplied project README.
See [this release's scope and checks](PUBLIC-RELEASE.md). This does not authorize
publishing private deployments, user records, supplier asset bytes, or teammate
video/photo materials. The items below preserve the earlier review checklist.

1. **Publish or keep private:** choose repository host/account/name/visibility and
   explicitly approve publication only after reviewing the staged archive.
2. **Copyright and contributors:** the user approved preparing MIT for original code,
   with `Copyright (c) 2026 M4KE contributors`. Confirm contributor authority and
   third-party provenance before publication. MIT preparation is not upload approval.
3. **Third-party provenance:** review normalized skills, referenced research,
   manufacturer source terms, dependency notices, model/runtime licences and
   contributor consent. Source URLs and hashes do not grant redistribution rights.
4. **Competition eligibility:** confirm the complete event rules and any sponsor-model
   requirement with the organizer. Do not replace the approved local model or claim
   StepFun usage solely because a slide names it.
5. **Team assets:** provide the actual team photo and approve the teammate-owned
   demonstration video/article and public URLs. This package does not publish them.
6. **Physical demonstration:** decide which claims are supported by observed hardware
   tests. Until then the physical car remains unverified; no purchase or printing
   authorization follows from the existence of a source package.

No passwords, keys, deployment endpoints, original private documents, runtime
history or user projects belong in the public source repository. The automated
checker is a bounded aid; review the final archive itself before approving release.
