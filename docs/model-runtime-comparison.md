# 本地模型与等待体验：2026-09-29 实测

## 最新补充：思考档位和装配修复

本机 `/api/show` 实际返回：`qwen3.8:27b` 支持 `false / low / medium / xhigh`，默认 `medium`；`qwen3.6:latest` 支持布尔开关。不能假设所有本地模型都有相同的控制方式。传输层现在按实际安装标签读取元数据：保留受支持的选项；仅有命名档位的模型将快速偏好映射到其 `low`（或声明的默认档位），记录实际采用值。明确请求但不支持的命名档位会报错。没有元数据的旧服务沿用原值并标注兼容状态，不伪称完成能力验证。模型、提示、输出格式、验证门槛和用户配置不自动改变；私有思考内容仍不保存或显示。参见 [Ollama 官方控制说明](https://docs.ollama.com/capabilities/thinking)。

额外的有限试验均未通过功能验收，未提升为生产设计能力：

- 私有通用锚点求解原型的 7 项数值控制和 48 项独立原生变换控制通过，但 Qwen 自选的装配关系错误：套环重叠、立柱穿底，跷跷板偏心且超出原包络。求解器正确计算错误意图，不等于设计正确。原型没有接入生产，也没有改写库模型。
- 对两份保留的失败模型调用现有局部补丁工具，并提供实际原生包围盒。直接回复约 25.93 / 24.74 秒，修改了几何，但仍有实体穿插；未改变需求、零件身份或检查阈值。比重写整份设计短，不等于修复成功。
- 同一失败任务改用该模型支持的 `low` 档位，每项仍在 180 秒截止前没有可见最终回答，两项超时均保留。该档位不设为生产默认。

校验错误另外改为指出完整字段，例如 `verificationRequests[4].diametralClearanceMm[0]`，而不是误导性的 `verificationRequests[4][0]`；数值范围与通过条件不变。候选模型下载状态属于私有运行记录，未安装完毕、未通过本机比较前不称为“最佳模型”。

## 结论先行

**尚未找到通过 M4KE 完整设计验收的“最佳模型”。** 已安装的 `qwen3.6:latest`（35B-A3B）在本轮小样本中最快，但几何质量不合格；不自动替换生产模型，也不宣称成功率已经提高。当前改动交付真实进度、失败留档、需求阶段对话、可恢复的追问历史和可选本机模型。

### 质量与负例

- 27B 收纳盒重复零件 ID，拒绝；122B 的采购数量不符合契约，拒绝。
- 35B 的收纳盒通过 JSON 契约，但真实 CAD 与独立测量显示 **没有三个敞开的格子**。原生验证失败；JSON 合法不是设计成功。
- 原始规则对 `dB`/`dB SPL` 字段和 GPIO 有过严之处：有的回答明确要求 SPL 校准却填写了 `dB`；GPIO 2/12 可输出但不属于产品的保守启动引脚白名单，而该白名单没有出现在比较题里。保留原始失败结果与语义复核，不把这些机械评分误差冒充模型推理失败。
- 随后通过真实隔离应用提交用户原始 ESP32、60 dB、PLA、F1、600 CNY 要求。35B 在 **360 秒测试窗口内进入第三次格式尝试，未交付合格草稿**；随后停止测试自有服务、确认退出并归还共享 GPU。没有手工代做汽车，没有放宽材料、控制器、SPL 或制造检查。
- 中断的旧生成器仅在结束时写完整回答，导致这次未留存已完成的中间输出。因此新增逐次原子落盘：已完成的失败回答和校验错误先保存，再进行下一次推理。`running` 记录不能当作已接受设计的来源。

## 本轮产品改进

1. 需求页直接问本地 Qwen；尚无模型或已有失败也能讨论。只读问答不会启动 CAD、改模型或授予 PASS。
2. 成功问答和候选说明最近 40 轮独立保存在 DGX；追问只带服务端读取的最近 8 条、每条最多 1200 字符。当前需求和版本证据优先于历史解释。
3. 生成展示模型名、真实已接收字符数、耗时和阶段；不显示私有思考内容，不编造百分比或零件预览。
4. 设置中列出实际安装标签、参数规模、量化、体积和 digest；选中后还需明确保存，不后台切换模型。
5. 修改始终是候选，确认才生效；选中上下文按提交时冻结，过期版本仍拒绝应用。
6. 静止 Three.js 场景按需渲染；拖动、阻尼、选择、加载完成和尺寸变化才请求帧。真实 WebGL 回归检查静止时无新增帧、选择后重新绘制，不重建渲染器或下载模型。
7. 对 HTTP 500 中明确的 CUDA 非法访问 / runner 终止，最多重试一次相同推理请求，共用原超时；不更换模型、重启服务、放宽校验或重放部分回答。失败后显示基础设施错误并保留重试计数。这是有界容错，不是已经修复下面的 35B 崩溃。

## 原生 vLLM 接入与角色化对话（2026-09-29 后续）

### 产品变化

- 推理服务显式选择 `ollama`（兼容旧设置）或 `vllm`。后者直接使用 loopback `/v1/models` 和 `/v1/chat/completions`，不经临时桥、不使用云端、不下载模型或启动容器。
- vLLM 模型列表展示真实 served ID；接口没有权重 digest 或大小时不编造。输出必须有合法结束原因与 SSE 终止记录；截断、异常、错误模型身份、工具调用和不完整流仍拒绝。不会把私有 reasoning 当成回复或 UI 进度。
- 设置只有保存后才应用。修改连接时不混用旧模型列表；任一工作流、只读问答或旧版推理正在进行时拒绝切换配置。
- 历史对话从单条 JSON 内的数组改成真正的 user / assistant 轮次；最新问题与当前版本上下文在最后。仍限制最近 8 条、每条 1200 字符，历史不成为工程证据。
