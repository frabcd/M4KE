- 已包含 ECHO F1 v1 / 大陆易购 CN v2 的 **CadQuery 参数化生成源码、ESP32 固件、接线显示、装配动画、3MF 排盘与配色源码**。生成方法见 [cad/designs/README.md](cad/designs/README.md)。
- 完成生成后，启动本地服务并打开 `/?build=echo-f1-cn-v2`；`&view=simulate` 是带轮组滚动的近似行驶预演。生成包缺失时页面明确提示，不自动伪造模型。
- CN v2 原生模型外廓约 **286 × 182 × 76 mm**；这是模型尺寸，不是实物公差证明。打印件与采购件分开，采购参考几何不能代替实物。
- `builds/` 内 STL、STEP、3MF、切片结果及运行检查记录由上述源码在本机生成，**不作为源码提交**。排盘需要单独准备官方 Bambu Studio profiles；仓库不附带厂家软件或耗材配置。准备齐模型、依赖和资源后，运行可不依赖开发电脑；DGX 断网冷启动验收仍待完成。
- 这是明确标识的人工设计基准包，不冒充 Qwen 从零生成的成果；历史生成/切片记录不代表新机器、新耗材或实际车辆已经通过验收。


> **基于 DGX Spark 的小型玩具设计与工程检查工作台**

**团队：逆熵｜第三届 DGX Spark 黑客松｜2026.09.29**

M4KE 是一个面向非工程背景创作者的小型玩具设计工作台。用户通过自然语言描述想制作的东西，AI 提出必要问题、生成结构化设计，并调用 CAD、工程计算和电气检查工具，将设计推进到可审阅、修改和准备装配的阶段。

M4KE 关注的不只是“生成一个看起来像样的 3D 模型”，而是把**设计、零件、工程检查、BOM、接线和装配说明**放进同一个可追踪的项目中。

> **当前状态：可运行的软件原型。** 已完成本地 Qwen 的既有设计修改试验；从零生成完整声控小车的端到端流程仍存在几何与接线问题，尚未完成实物验收。

### 只带 DGX：本地运行与行驶预演

- 在 DGX 预先安装模型、CAD、依赖和获准缓存的零件库后，使用 `npm run start:offline`。该模式拒绝在线模型桥接，并关闭联网检索；不依赖开发者电脑或内网穿透。
- 使用 `python scripts/dgx-preflight.py` 读取本机准备状态；`npm run benchmark:local -- ...` 对**实际安装的模型**进行需求保持、整批问题修复、选件修改的受约束评测，不偷偷替模型修补答案。
- 模型视口新增**行驶仿真（估算）**：当前几何进入 Three.js + Rapier 本地场景，可试响声前进、安静制动、障碍物碰撞，调整质量、轮径、电机和阻力假设；不改变打印文件或验证记录。
- **已在 DGX 核实 Ollama 的 `qwen3.5:122b-a10b` 并进行真实推理。** 从零生成完整小车、断网冷启动和实物运行仍未通过验收；模型已安装不代表完整工作流成功，也没有据此认定它优于其他模型。

配置与验收步骤见 [DGX-only 运行指南](docs/dgx-only-offline.md)，本轮证据与限制见 [测试记录](docs/local-sandbox-validation.md)。公开源码不包含模型权重、私人项目及第三方原始 CAD，首次准备仍需下载依赖与授权资产。

## ✨ 核心亮点

### 1. 从需求到装配的连续工作流

M4KE 将设计过程组织成完整流程，而不是一组互不相关的 AI 生成按钮：

| 阶段 | 系统支持 |
|---|---|
| **需求描述** | AI 追问关键缺口，区分用户答案与系统假设 |
| **设计生成** | 生成结构化设计、零件与候选方案 |
| **局部修改** | 根据选中的零件和修改意图生成候选版本 |
| **工程验证** | CAD、数值计算、电气检查与有界修复 |
| **导出与装配** | 模型、BOM、接线信息和逐步装配说明 |

设计候选不会未经确认直接覆盖已有版本；**数字检查通过 ≠ 实物测试通过**。

### 2. 让零件成为 AI 的上下文

用户可以在三维视口或零件大纲中选择具体零件，并查看其用途、位置理由、选型依据、材料和来源。

例如：

> “让外壳更像 F1 赛车。”

系统可以将当前选中的外壳作为修改上下文，而不是重新生成整个项目。

### 3. 三维预览与制造文件保持对应

前端使用 **Three.js** 展示模型，并记录毫米单位、源文件身份和几何哈希。

概念预览与原生 CAD 明确区分：CAD 失败时不会用一个“好看的示意模型”冒充真实工程结果。

### 4. 接线与装配说明跟随版本

电气视图区分电源、地线、信号和电机输出，并展示两端元件、引脚、建议线色和线规。

装配教程基于当前版本的真实网格生成步骤，并支持逐步查看、播放和重播。

## 🧠 Agent + Skills

M4KE 将**“提出设计”**和**“认定结果”**分开：

- **Qwen / Agent**：理解需求、选择方案、提出修改。
- **程序与工具**：执行受约束操作、生成 CAD、进行检查。
- **验证结果**：只能由对应工具产生，模型不能自行宣布“通过”。

### Skills

| Skill | 输入 | 输出 / 边界 |
|---|---|---|
| **需求与设计** | 用户需求、回答、目录、模型资料 | 关键问题或结构化设计 |
| **模型库与选型** | 组件身份、源文件、接口资料 | 可用几何、候选资料及缺口 |
| **局部修改** | 当前版本、选中件、修改意图 | 修改候选，不直接覆盖设计 |
| **验证规划与评审** | 设计、工具检查报告 | 检查重点与风险 |
| **受约束修复** | 设计及检查错误 | 提出修改并重新交给工具验证 |

核心闭环：

```text
工具发现问题
      ↓
Qwen 分析并提出修复
      ↓
生成新候选
      ↓
工具重新检查
      ↓
通过 / 继续反馈
```

修复采用**有界重试**，保留失败记录，避免无限循环或由程序偷偷生成“正确答案”。

## ⚡ DGX Spark 与本地推理

M4KE 的本地优先架构将模型推理、项目服务、资料处理和 CAD 工具组织在 DGX Spark 上：

- **GPU**：本地 Qwen 推理
- **CPU**：项目服务、资料处理与 CAD 任务
- **浏览器**：工作台交互与三维显示

2026-10-12 已核实的 DGX 配置：

| 配置 | 设置 |
|---|---|
| 模型 | `qwen3.5:122b-a10b` |
| 服务 | Ollama |
| 最大上下文 | `65536` |
| 自动价格检索 | 已启用；来源候选不等于完整可下单报价 |
| 应用源码 | PR #9 修复版本 `9652b1ea` |

下表保留早期 35B/vLLM 试验快照，不代表当前 DGX 配置：

| 配置 | 设置 |
|---|---|
| 模型 | `qwen3.6-35b-fp8` |
| 服务 | vLLM |
| 最大上下文 | `65536` |
| 最大序列并发 | `1` |
| KV Cache | FP8 |
| GPU memory target | `0.55` |

### 优化思路

- FP8 KV Cache 降低内存占用
- 限制并发，减少统一内存竞争
- 根据任务类型提供不同上下文
- 局部修改优先返回变更字段，减少完整重写
- 保留失败结果和真实运行阶段
- Three.js 视口按需更新，减少不必要的 GPU 工作

> 项目目前**没有进行自有数据微调、LoRA 或蒸馏**，也没有据此宣称通用设计成功率提升。

## 🔧 CAD 与元件模型库

M4KE 不把“能显示”当成“能装配”。

元件资产记录：

- 组件身份
- 来源
- 单位
- 原始坐标
- 文件哈希
- 接口与安装资料

并区分：

1. 可进入原生 CAD 流程的资产
2. 仅用于视觉参考的模型
3. 仍需审核的候选资料

采购信息和公开资料可通过本地目录、缓存与 MCP 接口提供给 Agent。检索结果带有来源与缓存信息，但**网址存在不等于实时库存、价格或型号兼容性已经确认**。

目前未接入可用的嘉立创 EDA PCB 自动布局布线服务，也不生成已验证的 Gerber。

## 🧪 验证与当前结果

历史声控小车是贯穿流程的一个测试场景，当时输入约束包括 **ESP32、PLA 外壳、F1 外形、约 600 CNY 预算**以及超过 60 dB SPL 时前进的行为。

当前记录：

| 测试 | 结果 | 说明 |
|---|---|---|
| 本地 Qwen 修改既有 F1 设计 | **成功完成一次案例** | 模型响应约 38.8 s；完整候选及检查约 184.6 s |
| 修改后的原生文件 | **几何真实变化** | 外壳、前翼、尾翼 STL 哈希改变；采购件保持 |
| 从零生成完整声控小车 | **未通过** | 提出 19 个零件、23 条连接；CAD 与电气检查失败，修复后仍未通过 |
| 历史软件回归 | **552 通过 / 6 跳过** | 早期版本快照；不代表当前源码 |
| PR #12 软件回归 | **580 通过 / 20 跳过 / 0 失败** | Linux CI 对应 `31b970e`；九个缺失供应商 CAD 的测试组另行延后 |
| PR #11 的一次 122B 隔离复测 | **有效澄清，约 102 s** | 两次完整响应；没有接受设计/CAD/价格，不是端到端成功 |
| 实物验收 | **尚未完成** | 暂不声称打印、装配或运动性能通过 |

这些结果对应特定输入、版本和测试条件，不代表长期稳定性或通用成功率。

## 📦 安装与运行

### 环境

目标环境：

- Linux aarch64
- Node.js ≥ 22.12
- Python 3.12
- 与 DGX Spark / GB10 匹配的 NVIDIA 驱动与推理环境

安装项目依赖并执行 smoke test：

```bash
python3 scripts/setup-submission.py --smoke
```

模型与 CAD 依赖须先独立准备；下面的命令不会下载模型。使用已核实安装该精确模型标签的本机 Ollama 服务：

```bash
export M4KE_INFERENCE_PROVIDER=ollama
export OLLAMA_URL=http://127.0.0.1:11434
export QWEN_MODEL=qwen3.5:122b-a10b
export PORT=4173
```

若使用另行准备的 35B/vLLM 服务，保留以下配置示例；它不是当前 DGX 部署配置：

```bash
export OLLAMA_URL=http://127.0.0.1:18007
```

## 🚧 当前限制与下一步

### 1. 更完整的问题反馈

一次收集所有可独立执行的几何、电气和参数检查，将相关错误一起反馈给 Qwen，而不是只返回第一个失败。

### 2. 提高组件接口质量

继续审核模型库中的：

- 单位
- 安装基准
- 孔位
- 端子
- 接口信息

扩大真正可以可靠用于工程流程的组件范围。

### 3. 建立固定端到端 Benchmark

使用相同的需求、资产版本和通过条件，对不同模型与推理配置比较：

- 成功 / 失败
- 耗时
- 人工决策次数
- 检查失败类型

### 4. 完成实物测试

实际采购、打印和装配，并测量：

- 尺寸配合
- 接线
- 声音阈值
- 运动
- 停止行为

再将实物结果反馈到软件检查和装配教程中。
